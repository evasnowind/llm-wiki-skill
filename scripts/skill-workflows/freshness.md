# 知识新鲜度与更新影响

用户询问“哪些知识需要复核”“原文更新影响了哪些页面”，或回答需要判断依据版本时读取。新鲜度判断针对库内已采用版本；原文片段的哈希核验仍按 [检索指南](query.md) 执行。

## 只读检查

```bash
node "${SKILL_DIR}/scripts/freshness-cli.js" scan "${WIKI_PATH}" --json
node "${SKILL_DIR}/scripts/freshness-cli.js" scan "${WIKI_PATH}" --path "wiki/topics/某主题.md" --json
```

默认有预算地检查 wiki，也可用重复的 `--path` 限定页面。检查不生成问题、不改正文、索引或日志。报告保留页面路径、原因、依赖版本、潜在传播路径和覆盖限制。

| 状态 | 如何表达 |
|---|---|
| `current` | 记录的依据仍对应本次检查可验证的当前采用版本；不代表事实已获真实性认证 |
| `stale` | 已确认引用文件变化或引用的是已被新版采用替代的资料修订；需要复核，不能据此直接判定结论错误 |
| `potential` | 来源提示、明确双链或受限间接依赖显示可能受影响；说明关联和传播路径，不冒充确定过期 |
| `unknown` | 缺失、外部编辑、损坏状态、未完成发布或预算不足，无法可靠判断 |
| `untracked` | 页面缺少可验证的采用依据；如需纳入跟踪，应重新整理证据并通过 Review 采用 |

只有与当前页面对应的已提交采用记录，才可提供确定的引用依据。手写 frontmatter 和页面标记只作线索；歧义链接不猜目标，循环与间接传播有深度限制。正文相同但附件已更新，也会形成新的素材修订；只捕获、尚未采用的新包不替代当前采用版本。

旧版原文仍可逐字节核验，这与它是否为最新依据分开。报告 `coverage.complete:false` 或缺少新鲜度信息时，明确说明限制，不把“未找到影响”写成“全库没有过期知识”。不自动读取外部来源目录或联网判断现实世界的信息变化。

## 显式跟踪待复核页面

用户已要求跟踪或处理影响时，选定页面后执行：

```bash
node "${SKILL_DIR}/scripts/freshness-cli.js" track "${WIKI_PATH}" --path "wiki/topics/某主题.md" --json
```

命令为符合条件的 `stale`／`potential` 页面建立 `unverified` Review 问题，相同页面及资料版本重复跟踪去重。检查与写问题之间再次验证路径版本；若来源或页面发生变化，重新检查后再跟踪，不复用旧判断。

后续研究、生成候选、核对及采用按 [Review 指南](review.md) 执行。只有正式采用成功才报告页面已更新或问题已解决；`current` 状态不自动关闭已有问题，取消候选也不会解决问题。

Node 不可用时可人工对照资料版本与引用，明确标为人工判断，保留待验证项；不要自动安装工具。
