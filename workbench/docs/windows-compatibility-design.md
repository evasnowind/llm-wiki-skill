# 工作台 Windows 兼容修复

## 范围与完成标准

覆盖原生 Windows 工作台的脚本执行、Git Bash 定位、系统目录选择、知识库名称，以及对应测试与 CI。保持现有 macOS 行为和 Linux 的明确降级入口，不增加运行时依赖或新的凭证／配置来源，不改冻结的 Skill 工作流。

完成时必须有命令参数与平台分支回归、真实临时脚本及知识库流程验证、Windows 原生 CI 定义、全仓检查和浏览器验证。当前主机的测试不能写成 Windows 实机已通过；原生 Windows 结果以实际 CI 记录为准。

## 脚本执行

- 初始化和图谱重建共用窄的 Bash 执行入口，复用 pi SDK 的公开 Shell 定位能力，识别 Git for Windows 的常见安装位置及已有 Shell 设置。
- `.sh` 必须由 Bash 显式执行；脚本路径和参数使用独立 argv，不将用户资料、库名、路径或用途文本拼成 Shell 命令。
- 对脚本路径和明确的路径参数作必要的平台转换，保留中文、空格、引号及用途文本原值。不能把 SDK 的 `sh` 回退误当成 Bash。
- 保留调用场景原有的环境隔离策略，同时提供 Windows 子进程必需的系统环境和 UTF-8 编码；不额外传递模型认证信息。
- 找不到 Bash 时给出可操作的安全提示。中止图谱生成时清理相关子进程，避免浏览器取消后后台继续运行。

## 系统目录选择

macOS 继续使用原有系统对话框。Windows 使用系统自带 PowerShell 与 WinForms 目录选择器，通过编码后的固定脚本启动，避免中文乱码和命令注入。不将用户输入插入 PowerShell 源码。

选择成功返回完整路径；取消返回空选择；失败沿用现有脱敏错误。请求中止或超时必须关闭启动的进程。Linux 等未实现平台保持“不支持系统选择器”的明确返回，用户仍可手动填写路径。

## 库名

校验最终将创建的目录名，并保留既有输入规范化语义。正常中文和空格名称继续支持；禁止 Windows 保留设备名、非法字符、控制字符和尾点等无法可靠跨平台保存的名称。错误在创建目录和启动脚本之前返回，避免留下半成品。

## 测试与 CI

- 纯命令契约覆盖 Bash 查找、缺失依赖、中文空格路径、特殊参数、平台环境、取消及错误；目录选择器测试不实际弹窗。
- 临时目录运行真实 Bash 初始化及相关图谱流程，核对生成内容与参数值，禁止访问用户知识库、真实凭证或外部模型。
- Windows 工作台 CI 使用包含空格的仓库路径，覆盖构建、类型检查、平台测试、入库队列、Markdown 检索与证据读取及真实浏览器主流程。
- 隔离测试同时处理 HOME、USERPROFILE、APPDATA、LOCALAPPDATA 和 pi 配置目录；不得以修改系统 API 的方式伪造平台通过。
- POSIX 权限断言只验证支持该语义的系统；Windows 验证实际读写和恢复行为，不能把 `0600` 视为 Windows ACL 的证明。
- npm 子进程通过 Node 和 npm 的 JS 入口启动，避免在 Windows 中直接执行 `.cmd` 或使用任意 Shell 拼接。
