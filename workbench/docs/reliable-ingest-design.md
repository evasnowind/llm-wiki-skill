# 工作台可靠入库

## 目标与边界

工作台接受一批素材后，任务应由后端持续执行。刷新页面、关闭任务面板或切换知识库不撤销已接受的任务；用户可以重新查看进度、明确取消或重试失败项。

本次默认的入库结果为：保留原始素材、生成素材摘要页、更新索引和操作日志。它不等同于 Skill 的完整 ingest，也不自动承诺完成实体页、主题页的抽取和合并。既有 Skill 工作流、知识库目录和原有批量消化接口继续保持兼容。

参考其他知识库应用的持久任务、检查点和写入协调方式，在本仓库独立实现；不复制其实现代码，不引入新的运行时依赖。

## 用户流程

1. 在现有批量消化入口确认知识库与素材范围。
2. 后端校验来源权限并保存不可变输入及任务记录，然后确认接受任务。
3. 入库面板按文件显示等待、处理中、保存中、完成、失败或取消。
4. 刷新后从后端读取任务快照；暂时断线只影响进度显示，不改变后台任务状态。
5. 完成项可以打开素材摘要；取消和重试通过明确操作发起，成功项不会随重试重复生成。

## 数据归属

- 原始素材、素材摘要、索引、操作日志属于知识库。
- 队列、来源快照、准备好的生成结果和恢复记录属于应用数据，保存在现有应用数据目录的 `ingest/` 下。
- 不把模型凭证存入任务记录。模型配置仅保存提供商及模型标识。
- 临时扫描编号只用于接收任务时的授权校验，不作为跨重启凭据。
- 后台任务始终绑定接受时的知识库，不依赖后来切换的当前对话或当前知识库。

## 执行与恢复约束

- 持久状态先保存成功，才能向前端确认任务已接受；损坏的状态不能被当作空队列覆盖。
- 输入在接受时固定。相同来源和相同内容重复提交时复用已有结果或任务；来源同名不等于来源相同。
- 模型只负责读取固定输入并生成内容，不能直接任意修改知识库。生成和发布分开，生成结果在发布前形成检查点。
- 生成可受限并发，同一知识库的实际发布必须协调，避免索引和日志相互覆盖。
- 原始素材与摘要采用稳定输出身份。发布完成但任务完成记录尚未落盘时，重启应识别并收口，不能再创建一份新页面。
- 多文件发布通过恢复记录或等价机制保证可重放；遇到外部未知版本停止并提示处理，不覆盖未知内容。
- 显式取消与发布共用执行状态约束。取消成功后，迟到的模型结果不能再写入；已经发布的内容不能被报告为从未发生。
- 瞬态错误有界重试；凭证、配置、权限和路径错误保留可操作的失败状态，不无限调用模型。
- 关闭服务时停止调度、终止生成并收口状态；重启后恢复未完成任务，提交检查点优先于重新生成。
- 写入前核验知识库和目标路径，拒绝符号链接逃逸、非法相对路径及已经失效的知识库。

## 接口与界面

新增可靠入库 JSON 接口：创建任务、按知识库读取任务、取消、重试。所有接口进入共享端点清单，沿用工作台来源、启动凭证、知识库登记与统一错误边界。

前端通过任务快照恢复并定期更新进度。知识库切换时立即切换显示上下文，并拒绝旧请求的迟到响应。关闭面板只隐藏界面，入口可以重新打开。

## 验收

- 同一输入重复提交不重复生成；不同路径同名素材不串用结果。
- 刷新、断线、切库后任务继续，旧知识库响应不污染新知识库。
- 重启覆盖等待、生成中、生成完成、部分发布、发布完成未记账等阶段。
- 单项失败不阻塞其余文件；取消、重试和晚到结果的竞态有可控测试。
- 来源授权、目标目录替换、符号链接、状态损坏与磁盘失败有明确失败路径。
- 原始素材、摘要、索引、日志可相互追溯，重放不重复追加记录。
- 契约、后端、前端 DOM、浏览器关键流程和仓库完整质量检查通过。

本次不增加复杂文档解析器、向量数据库、联网研究、目录自动监听或桌面打包。
