# Markdown 检索与引用溯源

## 目标

在现有工作台检索上增加章节级证据、标签和别名召回、受限双链扩展，并把回答中的引用连接到原文具体位置。知识综合与仅原文回答共用检索和引用身份，分别控制可用证据。

本次沿用现有本地 Markdown 知识库和模型运行时，不增加向量数据库、PDF 解析或运行时依赖，不修改成熟 Skill 工作流。

## 两种回答模式

- **知识综合**：基于当前知识库页面及相关原始素材回答，保留常规对话和工具能力，明确区分整理页与原始资料。
- **仅原文**：只把本轮检索到的原始 Markdown／文本片段作为依据。没有原文证据时直接说明，不调用模型补写答案。

仅原文模式使用独立内存会话，仅复用当前模型及认证。该会话不加载历史回答、生成页、库说明、上下文文件、Skill、扩展、提示词模板或工具，并关闭自动压缩；避免旧对话在压缩阶段先进入模型。结束后将本轮问题与安全结果保存到正常对话，供界面查看，下一轮仅原文回答仍重新检索。

## 检索

- 按 Markdown 标题、章节和段落组织片段，保留真实行号、标题层级及原文字符；代码围栏中的伪标题不改变章节。
- 标题、文件名、正文、常见 frontmatter `tags`／`aliases` 都可参与召回，中文查询支持合理的词片段匹配。
- 双链只扩展一跳，遵循明确路径和唯一裸名的解析规则，歧义不猜；关系仅作召回信号，不作为正文证据。
- 显式引用优先，但与自动召回共同遵守文件数和上下文预算。所有可点击证据必须实际进入本轮模型上下文。
- 仅原文模式的候选与扩展都限原始资料；原文提及列表也只列原始资料。整理页不回退成原文证据。
- 检索读取有边界，文件变化后不能沿用失效片段；扫描或输入受限时应明确提示，不能把未完整检查报告为确定无资料。

## 引用身份与对话历史

每条证据包括本轮编号、资料类型、知识库内相对路径、标题层级、行范围、完整文件哈希、片段哈希和有界原文。文件哈希基于原始字节，片段比较使用 LF 换行，保留其他原文字符。

模型以 `[1](#evidence-E1)` 引用本轮编号。界面只把当前回答已知的证据编号变成可点击来源；未知编号不触发文件读取，也不从模型链接拼接任意文件路径。

证据与模式经带有运行身份和顺序号的事件传输，并通过不进入模型上下文的会话自定义记录持久化，关联真实的本轮用户 entry。失败、取消、重复提问、分支或刷新不得把引用移到其他回答上；旧消息不补造证据。

## 原文阅读

独立的受保护只读接口接收 `{kbPath, citation}`，保留旧页面接口的职责。片段放在 JSON 请求体中，不放入 URL。

- 文件与片段匹配时定位并高亮对应原文块。
- 文件改变但同一片段仍唯一存在时，可以明确说明后重新定位。
- 片段消失或存在多处匹配时显示原文已变化，保留原引用说明，不把旧行号静默套在新内容上。
- 读取只允许知识库内明确支持的资料路径，拒绝隐藏元数据、路径越界、符号链接逃逸及过大输入。
- 关闭抽屉、换引用、切知识库或换对话后，旧读取响应失效；同路径不等同于同一来源。

## 界面

输入区提供紧凑的“知识综合／仅原文”选择，发送时捕获本轮模式和会话身份，生成中保持模式固定。回答保留自身模式和来源，引用点击后进入原文阅读。既有图谱、入库任务、普通页面阅读和快捷键继续可用。

## 验收

1. 固定的 20–30 条合成 Markdown 问题覆盖章节深处、标签、别名、双链、中文、歧义、无证据、预算与原文隔离，并标注期望来源或章节。
2. 真实 SDK 的假模型捕获实际输入，证明仅原文模式不带入整理页、历史、工具、Skill、上下文文件或压缩请求；取消与失败不影响后续普通回答。
3. 引用事件、请求身份、会话历史、重复问句、分支和终态顺序均有测试。
4. 安全读取、原文改写、重复片段、符号链接与跨知识库同路径场景有明确结果。
5. 真实浏览器完成提问、查看引用、原文定位、刷新历史、修改原文提示、切库隔离及两种模式；桌面和平板保持 Paper 阅读布局。
6. 全仓质量检查、浏览器主流程与视觉检查通过。测试使用临时知识库和假模型，不读取用户真实资料或调用外部模型。
