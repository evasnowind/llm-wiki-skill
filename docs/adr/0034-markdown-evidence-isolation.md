# 原文证据隔离与逐轮引用身份

## 决策

知识综合保留现有对话及工具语境，检索升级为章节与段落证据。仅原文模式使用独立的内存会话，只复用当前模型与认证，输入限于本轮问题及检索得到的原始 Markdown／文本片段。

独立会话禁用历史加载、自动压缩、工具、扩展、Skill、提示词模板和上下文文件。没有原文证据时本地返回资料不足，不调用模型。结束后将用户可见结果保存到普通对话；下一轮仅原文仍独立检索。

引用只对应实际提供给本轮模型的片段，以逐轮编号、知识库内路径、原文范围、文件及片段哈希确定身份。引用元数据通过不进入模型上下文的自定义会话记录保存，绑定真实用户 entry。查看原文使用受保护的只读 JSON 接口，原文片段不放入 URL。

## 备选与取舍

- 只靠提示词要求忽略旧内容：历史回答、库说明和工具仍可能进入实际模型请求，无法保证输入边界。
- 在普通会话的上下文事件里过滤：SDK 可能先压缩历史，再触发事件，过滤发生得太晚。
- 保存路径和行号：外部编辑后可能指向不同文字；只保存问句或时间又无法区分重复提问。
- 引入向量数据库：增加索引和依赖维护成本；先用本地章节、标签、别名与受限一跳链接召回验证日常 Markdown 场景。

仅原文减少可用上下文，也不能替代对模型结论的核对。普通知识综合继续承担跨轮讨论和操作型任务。

## 影响

- 界面在发送时固定模式与对话身份，历史回答保留自己的证据，未知引用编号不触发文件读取。
- 文件内容未变时精确定位；原片段仍唯一存在时明确提示并重新定位；片段消失或重复时提示已变化，不套用旧行号。
- 检索与阅读均限制可见资料路径和大小，拒绝隐藏文件、越界与符号链接逃逸。扫描受限时明确提示。
- 合成问题集与真实 SDK 假模型测试分别验证召回和实际请求隔离，不以提示词文本检查代替运行时验证。

实施与验收见 [Markdown 检索与引用溯源](../../workbench/docs/markdown-evidence-design.md)。
