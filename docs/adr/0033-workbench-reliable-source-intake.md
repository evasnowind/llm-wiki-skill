# 工作台可靠入库与 Skill 完整整理的边界

## 决策

工作台在既有批量入口增加后端持久入库任务，负责固定已授权素材、保存原文、生成素材摘要、维护索引日志，以及取消、重试和重启恢复。接受任务后，执行不依赖浏览器连接、当前对话或后来切换的知识库。

这是 ADR-28 能力边界的一个明确补充：可靠入库只提供受控的来源保留和摘要发布，不在工作台另造一套实体、主题抽取与合并规则。Skill 的完整 ingest、query、digest、lint 等工作流继续保持原有职责。

## 备选与取舍

- 继续只用请求内批处理：页面断开即取消，刷新后无法核对进度，不满足已接受任务的可靠性。
- 在后台给共享 Agent 任意写权限并自动重试：当前知识库状态可能随用户操作改变，多文件写入也难以证明完成，存在串库与重复修改风险。
- 重新实现完整 Skill ingest：将复制已经成熟的工作流和知识维护规则，扩大这次可靠性改进的范围。

采用只读生成与后端发布分离的方式。队列、来源快照、生成检查点和提交记录属于应用数据；原文、摘要、索引、日志属于知识库；模型凭证继续由既有认证体系管理。

## 影响

- 界面明确展示等待、处理、保存及终态，隐藏面板不取消任务。
- 生成可以受限并发，同一知识库的实际发布必须协调。稳定输出身份和可重放记录用于消除重启重复写入。
- 未知外部版本不会自动覆盖；显式重试可以在保留当前内容的前提下补齐本任务的索引和日志条目。
- 后续若要自动抽取、合并实体或主题，应另行设计结构化提案、证据校验和提交规则，并保持 Skill 与工作台只有一套知识维护语义。

实施和验收约束见 [工作台可靠入库设计](../../workbench/docs/reliable-ingest-design.md)。
